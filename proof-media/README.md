# TA GuruLabs — PROOF Media System

Public rule: **show the evidence, not the architecture.**

## Editorial engine
BUILD → ATTACK → FAIL/CORRECT → RETEST → PROVE → SHOW → INVITE.

A public proof may only say PASS or VERIFIED when the underlying Evidence Ledger contains the supporting run. Failed tests are publishable and valuable.

## Three recurring formats
1. **PROOF FILM** — 45–60 seconds, vertical-first. One claim, one attack, one outcome.
2. **FIELD NOTE** — LinkedIn post explaining what failed, changed, or was learned.
3. **PROOF DOSSIER** — public web record linking the claim to sanitised evidence.

## Voice
Sparse. Curious. Precise. No "revolutionary", "game-changing", fake urgency or generic AI hype. Prefer "workforce", "mission", "evidence", "investigation", "verified outcome".

## Brand
Black / warm white / restrained gold. Sound: low pulse, tactile clicks, silence before verdict. No stock-tech imagery. Never expose secrets, customer PII, internal prompts, credentials or proprietary implementation details.

## CTA by flagship
- TA VERIFIED: **Give the workforce a mission you think will break it.**
- PAYE Forensics: **Give us a difficult anonymised PAYE scenario.**
- AEGIS: **Think dating apps ask the wrong questions? Tell us what they should ask.**

## Publication gate
Evidence exists → RED review complete → sensitive data sanitised → claims match evidence → public asset approved.

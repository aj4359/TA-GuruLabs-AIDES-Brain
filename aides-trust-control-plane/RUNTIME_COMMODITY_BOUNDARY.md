# AIDES Runtime Commodity Boundary

AIDES must be able to consume a long-running external/cloud/open-source agent runtime without surrendering TA GuruLabs' accountability layer.

The runtime may own execution mechanics: sessions, tools, subagents, containers and long-running work.

AIDES retains:
- mission objective
- authority/permissions
- evidence obligation
- economic envelope
- acceptance criteria
- recovery/reversibility
- TA VERIFIED release decision
- institutional learning

Rule: **runtime is replaceable; accountability is not.**

The first spike therefore defines a provider-neutral MissionEnvelope and RuntimeReceipt. No migration to a specific vendor is implied until a candidate runtime passes the same proof gates.

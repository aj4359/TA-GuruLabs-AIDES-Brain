# Scout Proof-First Standard v1

Effective: 2026-10-01

## Mandatory AIDES execution record
Every material AIDE action must produce a durable record containing:
1. identity
2. authority / permission boundary
3. action
4. cost
5. evidence
6. outcome
7. value

No material autonomous action is TA VERIFIED without this record.

## Customer-facing proof sequence
MISSION -> WORK -> EVIDENCE -> COST -> RESULT -> VERIFIED

A demo must show completed work and evidence, not only capability or UI.

## Runtime boundary
TA GuruLabs owns the business control/evidence layer. Low-level sandboxing, isolation and enforcement runtimes are treated as replaceable infrastructure. Evaluate established runtimes before building commodity isolation internally.

## Intervention
Every material autonomous workflow must define stop, deny, escalate and human-review paths. High-impact actions require explicit authority.

## Build gate
BUILD -> TEST -> FAIL/CORRECT -> PROVE -> EXPAND.

New flagship expansion is blocked until the current flagship has reproducible proof or a documented commercial reason to proceed.

## Flagship allocation
- PAYE Forensics: revenue/proof priority.
- AIDES OS + TA VERIFIED: strategic platform/control plane.
- AEGIS: controlled 10-pair proof experiment before scale.
- No additional flagship is created under this standard without replacing one of the three or passing a written exception review.
